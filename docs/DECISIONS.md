| 6 | Swarm simulator: ~100 `SwarmShard` actors × ~100 simulated agents (SQLite rows), not 10k awake actors. Claim: "10,000 agents across 100 actors". | Each awake actor = ~2 OS processes. |
| 7 | 3 benchmark tasks (invoice, shipping, discount), not 5. Avneh writes a set; compare with Amar's. | Matches Benchmark section + time budget. |
| 8 | Ownership: Avneh = actors, orchestrator core, Relay, Jev, immune system, shared reasoning, ledger, benchmark harness, swarm engine. Avneh exposes a typed service + event bus (`orchestrator/src/contract.ts`, `orchestrator/src/service.ts`) that Amar's endpoints wrap. | Role docs. |
| 9 | **Dev model = `deepseek/deepseek-v4.1-flash-1017`** for worker, fallback judge and lesson writer (top level of config/models.json). Benchmark + demo use `MODEL_PROFILE=bench` → `openai/gpt-6-luna`. Supersedes #3's default. DeepSeek price varies by time of day, so the ledger relies on OpenRouter `usage.cost`. | User decision 2026-10-31. |
| 10 | Relay: `@agent-relay/sdk@15.0.1` runs **directly under Bun 1.4.2** (smoke 11:20: DM between two identities, channel post seen by `message.created` listener, idempotent resend returns same id, 409 `name_conflict`, reconnect by token). No `relay-bridge/` Node process. Only the engine needs Node 22. Server does NOT block sends after `workspace.release`, so the bus rejects released identities locally. Listener events carry empty metadata and no DM recipient, so the bus records its own sends and dedupes listener events by message id. | Failure-mode fallback not needed. |
| 10 | Jev thresholds **act 0.62 / pass 0.45** (was 0.85 / 0.15) and reworded `instruction_conflicts_spec` to judge observable behaviour, from real calibration (bench/jev-calibration/report.md). | 0.85 sent a clearly conflicting instruction (p=0.82) to fallback; old wording misread "integer cents internally". |
| 11 | DeepSeek calls: large `max_tokens` + `reasoning.effort: low`, reject `finish_reason != "stop"`, `provider.require_parameters: true`, pin one provider per run for prompt-cache hits (docs/SMOKE.md). | Truncated JSON at max_tokens 800; cache only hits on the same provider. |
| 12 | **Drift monitor: built, not claimed.** On real embeddings (synthetic runs) raw scoring caught 0/4 planted traps and contrast scoring 1/4 at zero false flags. Kept in code (default `contrast`), cut from the demo and Devpost claims unless real-run calibration improves it. | Spec: claim drift only with the hit rate measured. |
| 13 | **Swarm: 10,000 agents across 20 SwarmShard actors (500 each), measured 0 lost**: 100,000 changes, 2,963/s, peak 42 processes / 2.18 GB. Claim: "10,000 simulated agents across 20 durable actors". | 100-shard layout ≈ 200 processes. |
| 14 | Codex 0.157.1: `--ephemeral` breaks subagents (dropped; fresh `CODEX_HOME` per run instead); subagent tokens are missing from `turn.completed`, so the runner sums every thread's log; custom `worker.toml` agent type is unused by `spawn_agent`. | Measured in a real trial: 19/19 tests, 4 subagents. |
| 15 | **Similarity thresholds recalibrated: `case_similarity` 0.6 → 0.4, `chunk_similarity` 0.75 → 0.55** (config/thresholds.json). | Measured on real runs rhaip/rcudu with text-embedding-3-small (256d): a verified chunk scores 0.77–0.86 against its own subgoal but 0.27–0.59 against any other function's; the parse_line trap case scored 0.15–0.46 against other subgoals. At the spec values no chunk or case could ever reach another agent. Jev `lesson_relevant` ≥ 0.5 still gates case recipients. |
| 15 | **Codex baseline = v2 tasks.** v1 Codex rows are confounded: 52/64 agent pytest runs failed with "No module named pytest" (Codex shell resolved Homebrew python 3.14). Fixed in bench/codex/run.ts (per-run ZDOTDIR shim). v2: 9/9 pass, $0.0172 and 852k tokens per passing task, 5 trap hits during runs (0 in final code), 0 false completion claims. | docs/BENCHMARK.md |
| 16 | **Demo leads with a live 1,000-agent fleet with deliberate poisoning** (fleet-scale mode: agent state sharded across actors, aggregate `fleet.stats` + `fleet.grid` events). Codex benchmark is supplemental. A real recorded 1,000-agent run is the REPLAY fallback. | User decision 2026-10-31. |
| 17 | **Review fixes to the core loop.** Ledger row ids continue numbering after a restart (`Ledger.maxIndex(prefix)`), so a step re-executed after a crash records its new paid calls instead of dropping them as duplicates. Case posts and replies reach only that case's recipients (other agents get the lesson through the lessons block); the warden post describes the failure and never quotes the claim or test output. Delivery is marked durably (`CaseLibrary.markBroadcast`, with the thread root id) and reconcile re-broadcasts undelivered cases. Reassignments of failed slots are stored in Fleet (`Fleet.reassign`), loops that finish mark `Fleet.markDone`, and a finished agent that gets a reassigned function is restarted. Fault-drill entries fire on one generation (`gen`, default 1). On macOS the test run is sandboxed (no network, no reads under the repo); set `SS_TEST_SANDBOX=0` to disable. | Code review of the integration run. |
| 18 | **Immune memory on Supabase (opt-in).** Durable Actors stay the live roster and hot state; a Supabase Postgres table `cases` (pgvector `vector(256)`, HNSW cosine index, RPC `match_cases(query_embedding, task, k)`) is the cross-run memory of case files: upserted on case id right after `CaseLibrary.add`, and queried at run start (top 3 per function subtask, same task) to seed the Fleet lessons block. Off unless `SUPABASE_URL` + `SUPABASE_SECRET_KEY` (or `SUPABASE_SERVICE_ROLE_KEY`) are set; `IMMUNE_MEMORY=write` files without recalling (cold benchmarks); MOCK lessons/embeddings are never written. | Actor state is per library and per run; lessons learned in one run should protect every later run of the same task, and a Postgres + pgvector index scales to millions of cases where a per-run actor list does not. Plain PostgREST fetch, no SDK. Schema: [supabase/migrations](../supabase/migrations). |
